# Editor Theming

How the Modularity editor's look is put together, and how to change it.

A theme has two independent halves:

| Half | What it holds | Where it lives |
| --- | --- | --- |
| **Palette** | `ImGuiStyle`: `Colors[]`, rounding, padding, border sizes | `applyModularityStyle()` in `src/EditorUI.cpp` |
| **Shading** | `ImGuiShadeTheme`: gradients, bevels, per-edge borders | `applyModularityShadeTheme()` in `src/EditorUI.cpp` |

They are separate on purpose. A custom palette gets the depth for free, and a flat theme (Glass,
Slate, Pixel, Super Round, Imgui Default) stays exactly as flat as it always was.

---

## Widget shading (ModuGUI)

`src/ThirdParty/ModuGUI/imgui_shade.cpp` adds depth to flat rectangles: a vertical gradient over
the fill, a bevel (1px lit edge + 1px shaded edge) and optional per-edge borders. Nothing is baked
into a texture; it is all generated by the renderer.

The colors still come from `ImGuiStyle::Colors` exactly as before. A shade theme only says *how* a
given rectangle is lit, keyed by **class** (what the rectangle is) and **state** (how it is being
interacted with).

### Classes

`ImGuiShadeClass_` — `Generic`, `Window`, `Child`, `Popup`, `TitleBar`, `MenuBar`, `Button`,
`Frame`, `Header`, `Tab`, `TabActive`, `Grab`, `ScrollbarBg`, `TableHeader`, `Separator`.

`Generic` is the root of the inheritance chain and covers anything ModuGUI cannot classify,
including `RenderFrame()` called from application code.

### States

`ImGuiShadeState_` — `Normal`, `Hovered`, `Active` (held/pressed), `Selected`, `Focused`,
`Disabled`.

Dock tabs use `TabActive` vs `Tab` for selected/unselected, and the `Disabled` state for a tab
whose tab bar is unfocused (that is where a theme puts its "dimmed" shading).

### `ImGuiShadeParams`

One entry per (class, state). Every `ImU32` color field uses **0 as "not set"**, meaning "derive
this from the fill color". Use `IM_COL32(0,0,0,1)` if you genuinely want an invisible edge.

| Field | Meaning |
| --- | --- |
| `Flags` | See flags table below |
| `GradientTop` | Luminance added to the fill at the top edge, `-1.0 .. +1.0`. `0` = flat |
| `GradientBottom` | Luminance added at the bottom edge |
| `BevelSize` | Thickness of the highlight/shadow edges in **unscaled** px. `0` = no bevel |
| `BevelIntensity` | `0..1` opacity scale for derived bevel colors |
| `BorderSize` | Outline thickness in unscaled px. `< 0` = use the matching `ImGuiStyle` border size |
| `ColTopHighlight` | Line just inside the top edge. `0` = derive (light when raised, dark when recessed) |
| `ColBottomShadow` | Line just inside the bottom edge. `0` = derive |
| `ColInnerShadow` | Optional second line below the top edge. Only drawn when set |
| `ColInnerHighlight` | Optional second line above the bottom edge. Only drawn when set |
| `ColBorderTop/Bottom/Left/Right` | Per-edge outline colors. `0` = fall back to `ColBorderAll` |
| `ColBorderAll` | Outline color for edges with no per-edge color. `0` = `ImGuiCol_Border` |

Per-edge border colors are meant for square chrome (dock seams, toolbars). On a heavily rounded
rect the four edges are drawn as inset lines and do not meet at the corners.

### Flags

| Flag | Meaning |
| --- | --- |
| `ImGuiShadeFlags_Set` | Entry is authored. When clear, the whole entry resolves to its parent |
| `ImGuiShadeFlags_Recessed` | Sunken control: derived bevel is dark on top, light at the bottom |
| `ImGuiShadeFlags_NoGradient` | Flat fill even if the parent has a gradient |
| `ImGuiShadeFlags_NoBevel` | No highlight/shadow edges even if the parent has them |
| `ImGuiShadeFlags_InheritGradient` | Take `GradientTop`/`GradientBottom` from the parent |
| `ImGuiShadeFlags_InheritBevel` | Take `BevelSize`, `BevelIntensity` and the 4 bevel colors from the parent |
| `ImGuiShadeFlags_InheritBorder` | Take `BorderSize` and the 5 border colors from the parent |

### Inheritance

`(class, state)` → `(class, Normal)` → `(Generic, Normal)` → built-in default.

An entry without `_Set` inherits wholesale. An entry with `_Set` can still borrow individual
groups from its parent with the `_Inherit*` flags, so "the pressed button is the normal button
with an inverted bevel" is three fields rather than a duplicated entry.

Inheritance is flattened **once**, inside `SetShadeTheme()`. Drawing is a plain array lookup.

### `ImGuiShadeTheme`

| Field | Meaning |
| --- | --- |
| `Enabled` | Master switch. `false` = classic flat rendering, and no extra draw work at all |
| `GradientScale` | Multiplies every gradient. `1.0` = as authored, `0.0` = flat |
| `BevelScale` | Multiplies every `BevelIntensity` |
| `Scale` | DPI scale for `BevelSize`/`BorderSize`. Set by the editor from the monitor scale |
| `Params[class][state]` | The entries |

`Scale` is what keeps a 1px hairline one *physical* pixel: thicknesses are scaled and then snapped
to whole pixels with a 1px floor, so a hairline never lands on a half pixel.

### API

```cpp
const ImGuiShadeTheme&  ImGui::GetShadeTheme();
void                    ImGui::SetShadeTheme(const ImGuiShadeTheme& theme);   // flattens inheritance
const ImGuiShadeParams& ImGui::GetShadeParams(ImGuiShadeClass, ImGuiShadeState);

void ImGui::StyleShadeThemeFlat(ImGuiShadeTheme* dst);      // everything off
void ImGui::StyleShadeThemeDesktop(ImGuiShadeTheme* dst);   // generic shaded desktop-editor look

void ImGui::ShadeRect(ImDrawList*, p_min, p_max, fill_col, shade_class,
                      shade_state = Normal, rounding = 0.0f, draw_flags = 0);
void ImGui::ShadeRectEx(ImDrawList*, p_min, p_max, fill_col, const ImGuiShadeParams&,
                        rounding = 0.0f, draw_flags = 0);

ImGuiShadeState ImGui::ShadeStateFromInteraction(hovered, held, selected = false);
ImU32           ImGui::ShadeAdjustColor(ImU32 col, float luminance_delta);

const char*     ImGui::GetShadeClassName(ImGuiShadeClass);   // stable, used by the file format
const char*     ImGui::GetShadeStateName(ImGuiShadeState);
ImGuiShadeClass ImGui::FindShadeClassByName(const char*);    // -1 when unknown
ImGuiShadeState ImGui::FindShadeStateByName(const char*);
```

`ShadeRect()` is the public entry point for code that draws its own chrome. It behaves exactly
like `ImDrawList::AddRectFilled()` when shading is off.

### Third-party windows and ModuPaks

Nothing to do. The classification lives inside ModuGUI's own widgets, so any window built out of
`ImGui::Button()`, `InputText()`, `Selectable()`, `BeginChild()`, tabs, scrollbars and so on picks
up the active theme automatically. Only code that hand-draws rectangles needs `ShadeRect()`.

### Cost

- The gradient re-colors the vertices `AddRectFilled()` already emitted
  (`ShadeVertsLinearColorGradientKeepAlpha`). No extra geometry, no extra draw call.
- Bevels and borders are 1-2 `AddLine()` calls, and only when the theme asks for them.
- No allocations, no containers, no per-frame caches. Inheritance resolution happens on theme
  change, not per widget.
- With `Enabled = false` the draw path is the original `AddRectFilled()` call and one bool test.

## The default Modularity theme

`applyModernTheme()` installs `applyModularityStyle()` + `applyModularityShadeTheme()`.

Palette: violet-tinted greys built around the logo's purple, ordered darkest to lightest as
input field < panel interior < window body < chrome, which is what makes a field read as a hole
and a toolbar as a shelf. Accent is `#9473E6`.

Shading: `StyleShadeThemeDesktop()` plus Modularity's own violet highlights. Every explicit edge
color is alpha-blended rather than opaque, so edges read as shading instead of as drawn outlines,
and translucent themes are not punched through.

Rounding is moderate (window 9, frame 6, tab 7) rather than the near-pill radii of the Glass
theme: a 12px radius on a 20px-tall field turns the control into a lozenge and eats the highlight.

### Built-in presets

| Preset | Shading |
| --- | --- |
| **Default** | Modularity shaded theme |
| Glass | flat (the previous default; its translucency is the effect) |
| Slate | flat |
| Imgui Default | flat |
| Pixel | flat |
| Super Round | flat |

## Persistence and compatibility

Presets live in `<project>/ProjectUserSettings/EditorUI.ini`.

- The `ImGuiStyle` half is still the hex blob it always was. Blob decoding is now
  length-tolerant: a blob shorter than the current `ImGuiStyle` decodes as a prefix and the
  remaining fields keep their current values, instead of the preset being dropped.
- The shade half is written as text, and only for entries that are actually authored:

  ```
  stylePreset0_shade=1 1.0000 1.0000
  stylePreset0_shade.Button.Normal=1 0.045 -0.04 1 1 -1 0x22ffb2c6 0 0 0 0 0 0 0 0
  ```

  Fields in order: `Flags GradientTop GradientBottom BevelSize BevelIntensity BorderSize`
  followed by the 9 colors as packed `ImU32` (`ColTopHighlight`, `ColBottomShadow`,
  `ColInnerShadow`, `ColInnerHighlight`, `ColBorderTop/Bottom/Left/Right`, `ColBorderAll`).

- Shading is **on by default**. A user preset with no `shade` lines gets the Modularity shading;
  a preset that stores `shade=1` with no entries behind it (which shades nothing, and is what the
  Style Editor's toggle used to produce) is repaired with the Modularity entries while keeping its
  own `GradientScale`/`BevelScale`. Built-in presets are exempt: Glass, Slate, Imgui Default,
  Pixel and Super Round are deliberately flat and stay that way.
- To make a preset flat, save it with shading switched off. `shade=0` is stored and honoured.
- Class and state names are a file format: they are never localized and never renamed. A name this
  build does not know is skipped rather than treated as an error, so a theme written by a newer
  build still loads.
- `themeVersion=3` marks the shaded era. As with the version 2 bump, the loose `color.*` dump of
  the live style from an older file is skipped, so an already-opened project does not resurrect
  the previous palette over the new default. Saved presets are never version gated.

## Live theme file (hot reload)

Optional, read-only, never written by the editor:

```
<project>/ProjectUserSettings/EditorTheme.modutheme
```

Same syntax as above minus the `stylePresetN_` prefix:

```
# comments and blank lines are ignored
color.WindowBg=0.149,0.129,0.204,1
shade=1 1.0 1.0
shade.Button.Normal=1 0.045 -0.04 1 1 -1 0x22ffb2c6 0 0 0 0 0 0 0 0
```

**Style Editor → Write Theme File** dumps the live palette and shading into this file, so a theme
can be turned into an editable config instead of only living in a preset blob.

The editor stats the file about once a second and re-applies it whenever it changes, so a theme
can be iterated on without restarting. Only the keys present in the file are applied over the
live theme. Delete the file and the editor returns to the active preset on the next preset switch
or restart.

## Adding a widget class

1. Add the enum value **at the end** of `ImGuiShadeClass_` in `imgui.h`, before `_COUNT`.
2. Add the matching name to `GShadeClassNames[]` in `imgui_shade.cpp` (the static assert will
   catch a mismatch).
3. Pass it from the widget: `RenderFrameShaded(..., ImGuiShadeClass_Yours, state)` for a normal
   frame, or `ShadeRect()` when drawing straight to a draw list.
4. Give it defaults in `StyleShadeThemeDesktop()`. Skip this and it inherits `Generic`, which is
   a valid outcome.
